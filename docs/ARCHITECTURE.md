# ColorFlow 架构说明

## 为什么不是 OpenFX / DCTL 单节点插件

三件事的性质不同：

| 需求 | 需要的接口 | 单节点 DCTL/OFX 能否完成 |
| --- | --- | --- |
| 按素材建时间线 | 媒体池、项目设置、时间线 API | 不能 |
| 一键还原/版本回退 | 节点图、调色版本、CDL/LUT 写入 | 不能 |
| 镜头颜色匹配 | 逐镜头抓帧、跨镜头统计、节点写入 | 不能 |

所以产品形态是 **Workflow Integration 面板 + 调色节点写入**：

- 面板负责建线、分析、批量调度、版本备份；
- 真正作用到画面的仍是 Resolve 节点里的 DCTL 或 CDL；
- 用户可以继续在 Color 页面手动微调，不会被锁死在插件里。

## 数据流

```
媒体池 / 时间线
      │
      ├─ 建线：分辨率 + 帧率 + 名称排序 → CreateTimelineFromClips
      │
      └─ 调色：SetCurrentTimecode → GetCurrentClipThumbnailImage
                    │
                    ├─ 解码 RGB → 线性光统计（p50、p85/p15、中性轴、饱和度）
                    ├─ 生成校正模型（曝光、白平衡、对比、饱和）
                    ├─ DWG → 场景域 DCTL → LUT/ColorFlow/*.dctl → SetLUT
                    └─ Rec.709 → 原生 CDL → SetCDL
```

## 安全模型

1. 写入前可选创建调色版本，原版本保留；
2. 写入失败时自动载回原版本；
3. 面板记录本次操作涉及的镜头与版本名，提供“撤销上次写入”；
4. 默认只写“疑似空白”节点；非空节点需要显式勾选；
5. 不自动删除素材、时间线或项目。

## 匹配模型

匹配不是把目标画面的每个像素映射到参考图，而是估计四个一阶校正量：

- 曝光：`log2(ref.p50 / target.p50)`，限制在 ±2 EV；
- 白平衡：参考与目标在近中性中间调上的 `log2(R/G)`、`log2(B/G)` 差值，限制在 ±0.30；
- 对比：`ref.p85/p15` 与目标的比例，限制在 0.80–1.25；
- 饱和度：参考与目标中位饱和度的比例，限制在 0.80–1.25。

如果画面里没有足够的近中性像素，白平衡置信度会下降，避免把大面积色墙或夕阳误判成白平衡错误。
